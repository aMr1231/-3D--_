# Twinline — цифровой двойник предприятия и 3D-тур

Рабочий прототип для студенческого хакатона «Цифровой двойник предприятия и 3D-туры по производству». Веб-система моделирует производственную линию, находит перегруженные участки, сравнивает сценарии изменений и проводит интерактивную 3D-экскурсию, где каждый объект связан с этапом процесса и рассчитанной метрикой.

> **Данные предприятия демонстрационные.** Предприятие вымышленное, показатели синтетические, но внутренне согласованные: их вычисляет одна и та же модель линии. Интеграций с ERP, MES и 1С нет (по ТЗ).

**Стек:** фронтенд — React 19 + TypeScript + Vite; сервер — **Laravel 13** (PHP 8.3+), база SQLite (для эксплуатации — MySQL или PostgreSQL).

## Быстрый старт

Нужны Node.js 20.19+, PHP 8.3+ и Composer. На Windows: `winget install PHP.PHP.8.4`, Composer — с [getcomposer.org](https://getcomposer.org/download/) (или всё сразу через Laravel Herd).

```bash
npm run setup
```

```bash
npm run dev
```

`setup` ставит зависимости фронтенда и сервера (`npm install`, `composer install`), создаёт `backend/.env`, ключ приложения и базу с демо-данными. `dev` запускает Laravel (http://127.0.0.1:8000) и Vite (http://127.0.0.1:5173), который проксирует `/api` на Laravel. Откройте **http://127.0.0.1:5173**. Если порты заняты, их можно сменить переменными `TWINLINE_WEB_PORT` и `TWINLINE_API_PORT`.

| Учётная запись | Логин / пароль | Доступ |
|---|---|---|
| Руководитель производства | `manager` / `demo` | Все разделы и управление пользователями |
| Гость экскурсии | `guest` / `tour` | Только 3D-тур, без финансовых показателей |

Кроме демо-учёток работает **регистрация**: новый пользователь получает роль «Гость экскурсии», полный доступ выдаёт руководитель в разделе «Пользователи».

## Команды

```bash
npm run dev         # Laravel + Vite в режиме разработки
npm run build       # сборка фронтенда в backend/public/app
npm start           # рабочий режим: Laravel отдаёт API и собранный фронтенд на http://127.0.0.1:8000
npm test            # все тесты: Vitest (модель, хранилище) + PHPUnit (сервер)
npm run test:web    # только тесты фронтенда (27)
npm run test:api    # только тесты сервера (26)
npm run typecheck   # проверка типов TypeScript
```

Любая команда artisan: `node scripts/backend.mjs <команда>` (скрипт сам находит PHP, даже если он ещё не в PATH).

## Сервер (Laravel)

- **Авторизация:** серверная сессия в зашифрованной httpOnly-cookie (`SameSite=Lax`, 12 часов, в БД — таблица `sessions`), CSRF-токен в заголовке `X-XSRF-TOKEN`, пароли — bcrypt, повторная генерация сессии при входе.
- **Роли:** `manager` и `guest`, проверка на каждом запросе (middleware `role:manager`); смена роли и удаление действуют сразу.
- **Защита:** 5 неудачных входов → блокировка на 15 минут; одинаковое время ответа для существующих и несуществующих логинов; проверка всех входных данных (FormRequest) с отбрасыванием лишних полей; заголовки безопасности (CSP, X-Frame-Options, HSTS по HTTPS и др.); журнал действий.
- **Данные:** сценарии и журнал прогонов хранятся на сервере и общие для руководителей; в браузере — только выбор активного сценария.
- **152-ФЗ:** собираются только логин и пароль (хранится хеш); без ФИО, e-mail и телефонов.

API и подробности — [`docs/02-architecture.md`](docs/02-architecture.md#29-авторизация-и-персональные-данные), развёртывание (HTTPS, nginx, кеширование, OPcache) — [`docs/08-deployment.md`](docs/08-deployment.md).

## Что внутри

| Раздел | Маршрут | Возможности |
|---|---|---|
| Обзор производства | `/` | Состояние линии, главная цифра выпуска и живая мнемосхема (клик по участку → двойник), подсказки при первом входе, KPI с трендами, динамика выпуска с событиями, перегрузки с рассчитанными рекомендациями, таблица участков, последние расчёты |
| Цифровой двойник | `/twin` | Мнемосхема на React Flow: поток, очереди, перегрузка; слои «загрузка / ожидание / стоимость»; паспорт участка; списочный вид для телефона |
| Сценарии | `/scenarios` | Редактор нагрузки и параметров участков, расчёт, «база → сценарий» по участкам, вклад участков во время цикла, сохранение на сервере |
| Аналитика | `/analytics` | Мощность и факт, загрузка, структура времени цикла, накопление очередей, затраты, чувствительность «±1 ресурс», сравнение сценариев |
| 3D-тур | `/tour` | Цех на Three.js: зоны участков, метки с кольцами загрузки, маршрут экскурсии, живые метрики и кейсы, переходы в двойник и аналитику; 2D-план без WebGL |
| Пользователи | `/users` | Роли, удаление, журнал действий (только руководитель) |

Путь руководителя и сценарий показа — [`docs/07-demo-script.md`](docs/07-demo-script.md).

## Модель расчёта

Аналитическая модель последовательной линии (теория очередей), без случайных чисел: мощность участка `μ = c · 60 · скорость · готовность / t`, поток по маршруту с перегрузкой при `λ > μ`, ожидание по формуле G/G/c Кингмана–Сакасегавы, время цикла, НЗП (закон Литтла), затраты и себестоимость. Формулы — [`docs/02-architecture.md`](docs/02-architecture.md#24-метод-расчёта), код — `src/domain/simulation`.

```
  components/, features/  дизайн-система и разделы
docs/                     требования, архитектура, модели, тесты, развёртывание
```
